# Статусы оплаты в группах — согласованная механика (4 статуса)

> Дата согласования: 2026-08-24. Ветка: `main`.
> Причина: тренер видел «оплатили 30+», а фактически оплачено ~16. Приложение
> раздувало счётчик, засчитывая переходящие абонементы прошлого месяца как оплату
> текущего.

## Модель

### Привязка оплаты к месяцу (ФОТ)
Платёж относится к месяцу поля `group_payments.month`, независимо от даты внутри
месяца. **ФОТ и выручка считаются только с оплат этого же месяца, переходящие с
прошлого не учитываются.** Проверено: все загрузчики оплат для ЗП используют
`.eq('month', …)`; period-логика (`getActiveGroupPaymentsMap`) в ЗП не участвует.

### Срок действия абонемента
Абонемент действует **один календарный месяц: от дня оплаты к тому же дню
следующего месяца** (оплата 7 июля → действует до 7 августа). Край месяца
клампится (31 янв → 28/29 фев). Заменяет прежний `+29 дней`.

### Дефолт даты начала
При отметке оплаты `sub_start` по умолчанию = **фактическая дата оплаты (сегодня)**,
а не 1-е число просматриваемого месяца.

## Четыре статуса (для текущего месяца, опорная дата = сегодня)

| Статус | Правило | В ФОТ месяца |
|---|---|---|
| 🟢 **Оплатили** (этот месяц) | есть оплаченная строка `month = текущий` | **да** |
| 🟡 **Оплатили в том месяце** | нет строки за текущий, но прошлый абонемент ещё действует (`sub_end ≥ сегодня`) | нет (учтён в ФОТ прошлого) |
| 🔴 **Без оплаты** | активен, покрытия нет (истёк или не платил) | нет |
| ⚪️ **Ушли** | `is_active = false` | нет |

Опорная дата: для текущего месяца — сегодня; для прошлого месяца — последний день
того месяца; для будущего — первый день.

«Оплачено сейчас» = 🟢 + 🟡. «Сумма оплат / ФОТ» = только 🟢 (месячные строки).

## Что затронуто

| Экран / файл | Было | Стало |
|---|---|---|
| Хаб группы (`renderGroupDetail`) | строка «Должники: N» (по периоду) | 4 счётчика 🟢🟡🔴⚪️, тап → список с фильтром |
| Список детей (`renderGroupChildrenScreen`) | бейдж «Оплачен/Не оплачен» | 4-цветные бейджи + плитки-фильтры; ушедшие видны под фильтром ⚪️ |
| Отчёт по детям (`renderGroupMonthReport`) | «Оплатили» по периоду (35) | 4-статусная сводка; «оплачено сейчас» + «сумма оплат» раздельно |
| Excel «Ведомость» (`exportChildGroupExcel`) | колонка «Оплачено» ✅/❌; ушедших нет | колонка «Статус» (4); ушедшие включены; итоги по 4 статусам; сумма только с 🟢 |
| `calcGroupSubEnd` | `+29 дней` | `+1 календарный месяц` |
| Дефолт `sub_start` | 1-е число месяца | сегодня |

Единый источник статуса — `DB.getGroupStatusMap`. Меняем расчёт в одном месте —
синхронно меняются хаб, список, отчёт и Excel. Расхождение «экран 35 ↔ Excel 10»
устраняется: статус и деньги перестают выдавать себя друг за друга.

## Что НЕ меняется
- ФОТ/ЗП — механика корректна, остаётся «только текущий месяц».
- Лист Excel «Посещаемость» (✓/✗ по датам) — без изменений.
- Колонки «Начало абонемента» / «Конец абонемента» в Excel — обе сохранены.
- `getActiveGroupPaymentsMap` остаётся для прочих потребителей (`db.ops`).
